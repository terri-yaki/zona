# Zona on iOS widgets and Shortcuts

These features are included in a native iOS build. Expo Go and an OTA update
cannot add the WidgetKit extension or App Intents metadata to an older binary.

## Inbox widget

The `ZonaInboxWidget` supports small and medium Home Screen families plus the
circular, rectangular, and inline Lock Screen families. It shows only bounded
presentation data: unread count, latest unread title, source snapshot, and
severity color. It never receives a source token, Supabase session, attachment,
metadata object, account ID, or notification ID.

The app refreshes the snapshot after an unfiltered inbox synchronization.
iOS decides when to render the extension, so the widget is glanceable state,
not proof of real-time push delivery. Tapping it opens Zona through the existing
`zona://` scheme.

Configuration lives in `zona/app.json`, the SwiftUI layout lives in
`zona/widgets/ZonaInboxWidget.tsx`, and the safe prop builder lives in
`zona/src/lib/inbox-widget.ts`.

## Shortcuts actions

The local Expo config plugin adds two App Intents to the main iOS target:

- **Open Zona Inbox** launches Zona and is offered as an App Shortcut and Siri
  phrase.
- **Prepare a Zona Alert** accepts a title and body and returns a JSON request
  body that can feed a later Shortcuts action.

Preparing JSON does not send an alert and never asks Shortcuts to store a Zona
source token. A sender still calls the documented `/notify` endpoint with its
own bearer token and idempotency key.

The native source is generated by
`zona/plugins/with-zona-shortcuts.cjs`. Run Expo prebuild on macOS and confirm
`ZonaShortcuts.swift` belongs to the main Zona target whenever the plugin or
Xcode version changes.

## Release checks

1. Build a new preview or production binary; do not use OTA for native changes.
2. Add every supported widget family and confirm empty and unread states.
3. Tap the widget from Home Screen and Lock Screen.
4. In Shortcuts, run **Open Zona Inbox** with Zona terminated.
5. Run **Prepare a Zona Alert** with quotes, Unicode, and line breaks, then
   verify the returned text is valid JSON.
6. Confirm Android builds contain neither the iOS widget target nor App Intents
   source.
